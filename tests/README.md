# Tests

Общий каркас проверок репозитория и будущих компонентов. Тесты должны проверять наблюдаемое поведение публичных границ.

- `unit/` — быстрые изолированные проверки;
- `integration/` — проверки взаимодействия компонентов на выделенном стенде;
- `security/` — проверки security-контролей и отказных сценариев.

`security/test_compose_policy.py` проверяет нормализованный вывод
`docker compose -f deploy/docker-compose.yml config --format json` для
безопасных настроек по умолчанию. Нужен установленный Docker CLI с Compose
plugin; работающий Docker Engine для этих статических тестов не требуется.
Набор автоматически входит в `make test`, `make quality` и CI Tests.

Привилегированные сетевые проверки и активное реагирование выполняются только в явно выделенной тестовой среде.

## Поведенческий стандарт

Тесты проверяют публичную границу и наблюдаемый результат: возвращаемое значение,
вывод CLI, код завершения или репозиторный контракт. Они не проверяют порядок
внутренних вызовов, приватные функции или расположение временных файлов.

Smoke-проверка запускает пакет из установленного окружения и меняет рабочий
каталог за пределы репозитория. Репозиторные проверки запускаются через
`pytest` и должны включать отрицательный тест для `ruff format --check`, чтобы
CI не исправлял исходники молча.

Минимальная поддерживаемая версия Python задается в корневом `pyproject.toml`
и проверяется в CI matrix. Команда `make test` применяет ненулевой coverage
gate; его ослабление требует отдельного обоснованного решения.
