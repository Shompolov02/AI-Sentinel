# Core intake v1 — входы и команды Cowrie (#45–#48)

Контракт утверждён 2026-10-20; основание — #44 и ADR 0002.
В #46 добавлен нормализованный успешный вход; #47 добавляет политику
Low/Medium/High по ADR 0004. #48 добавляет команды и локальный Guard по ADR 0005.
Сырые записи целиком и пароли входа не копируются; текст команды включается
в нормализованное событие и может содержать чувствительные данные.

`POST https://core-intake:8443/internal/events`, `Content-Type: application/json`,
`Authorization: Bearer <collector token>`, с проверкой CA и имени сервера.

```json
{
  "schema_version": 1,
  "event_id": "5697880a-7ac4-43db-bfe9-1692ee3cefc7",
  "occurred_at": "2026-10-20T10:00:00Z",
  "received_at": "2026-10-20T10:00:01Z",
  "event_type": "login_attempt",
  "cowrie_event_type": "cowrie.login.failed",
  "sensor_id": "cowrie-lab",
  "session_id": "synthetic-session-1",
  "source_ip": "192.0.2.10",
  "source_port": 41000,
  "protocol": "ssh",
  "destination_port": 2222,
  "raw_record_ref": "synthetic:login-1",
  "login": {
    "username": "synthetic",
    "outcome": "failure",
    "password_length": 12
  }
}
```

Общие поля и `login` обязательны для попытки входа; для команды вместо `login`
обязателен `command` (см. дополнение #48). Неиспользуемый payload можно опустить
или передать как null; одновременно два непустых payload запрещены.
Неизвестные поля запрещены, включая вложенные payload. Время включает часовой пояс;
ID события — UUID; source_ip — IPv4/IPv6; порты — целые 1–65535; длина пароля —
целое 0–65535. Строковые идентификаторы, логин и непрозрачная ссылка — 1–256
символов, протокол — ssh/telnet. HTTP proxy ограничивает тело 64 KiB.

Ответ 202 появляется после фиксации события и queued-задачи, до ожидания анализа:

```json
{
  "task_id": "990c9a94-d034-49c1-99fa-14a531e4939c",
  "correlation_id": "990c9a94-d034-49c1-99fa-14a531e4939c",
  "state": "queued"
}
```

Повтор того же нормализованного содержимого и event_id даёт прежнюю задачу
с её текущим состоянием. Изменение содержимого с тем же ID — 409.
401 означает отсутствие разрешения; 422 — неверный JSON-контракт; 503 — заполненную
очередь или недоступную SQLite. В этих случаях новая задача не подтверждается.
Построение идентификатора настоящим нормализатором определено в ADR 0003 (#46).

Состояния: queued → processing → completed или failed. При failed вердикта нет.
`GET /api/tasks/{task_id}` требует пользовательский сеанс SecOps и возвращает
`task_id`, `correlation_id`, `state`, `created_at` (Unix UTC), `event`, `history`,
`verdict`, `analysis`, `evidence`, `audit`. Несуществующая задача — 404.
Для входа `analysis=null`; для команды это сохраняемый результат анализа,
доступный и при `failed`. До завершения обработки он может быть null.

Вердикт попытки входа содержит severity=Low/Medium/High, reason, analysis_method=Rules,
rules_version=cowrie-login-v2, guard_result=not_applicable, mitre_attack=null
(«не определена») и evidence_ids. Успех получает High; отказ — Low при числе
отказов 1–4 и Medium начиная с пятого. Critical этими правилами не формируется.
Счёт общий для одного IP по SSH/Telnet, сессиям и сенсорам. Успех не увеличивает
и не сбрасывает число отказов.

Окно включительно: [occurred_at − 300 секунд, occurred_at]. При приёме фиксируется
число уже принятых уникальных отказов, включая текущий. Поздняя доставка не
пересматривает прошлые оценки; события с более поздним occurred_at в окно
текущей записи не входят. received_at и часы Core не задают окно. Дубликаты и
отклонённые запросы в счёт не входят. Снимок счётчика сохраняется до ответа 202
и переживает задержку worker и перезапуск.

Evidence содержит UUID id, event_id, raw_record_ref, source_kind
(synthetic/reference_only), facts с outcome, protocol, cowrie_event_type,
failure_count, window_seconds=300, window_basis=occurred_at и window_end.
Причина объясняет результат и порог. Core не открывает ссылку как файл или URL.
Сырые записи на странице пока не выдаются. Старые готовые/failed задачи,
Evidence и аудит при обновлении не пересматриваются.

Аудит задачи содержит id, at (Unix UTC), action, actor, task_id, correlation_id и
details. Действия: event_accepted, processing, verdict_created, completed/failed.
Отдельные записи login_succeeded фиксируют роль SecOps и время успешного входа,
видны в списке задач. Записи не перезаписываются. Полный текст HTTP-запросов,
пароли и токены в аудит не включаются.

`GET /login` — форма; `POST /login` принимает JSON `{ "password": "…" }` и выдаёт
HttpOnly/SameSite=Strict cookie. GET /tasks и /tasks/{task_id} — страницы только
чтения. Успешный явный просмотр продлевает idle timeout 1800 секунд; poll=1 не
продлевает его. Действует один SecOps, без журнала неудачных входов и без задержки
после неверных паролей. Подробности запуска и ротации — в Core runbook.

## Дополнение #50: поиск и фильтр списка

`GET /tasks?q=…&state=…` ищет по полному UUID задачи или буквальной подстроке
без учёта регистра. Пробелы по краям запроса удаляются; пустой запрос не
ограничивает список. `%` и `_` не являются шаблонами. `state` допускает пустое
значение (все состояния), `queued`, `processing`, `completed`, `failed`;
неизвестное состояние даёт 422. Поиск и состояние применяются совместно ко всей
сохранённой истории до ограничения выдачи 100 последними подходящими задачами.
Пустая выдача явно обозначена, значения сохраняются в форме и при обновлении
через `poll=1`, которое не продлевает сеанс. Права, запрет кэширования и режим
только чтения остаются прежними. Список показывает время приёма Core в UTC;
без вердикта уровень отображается как «—».

Список автоматически перечитывается примерно каждые 10 секунд; карточка — пока
задача в `queued` или `processing`. Обновление выполняет только GET с `poll=1`
и показывает актуальные состояние и результат. В `completed` и `failed`
автообновление карточки прекращается. По истечении 30 минут без явных действий
следующий фоновый запрос получает 401 и страницу со ссылкой «Войти», без данных
задачи и дальнейшего автообновления. Настройки и состояние задачи через страницу
не изменяются.

### Сигналы Core

Список показывает текущие критические проблемы и последние 100 сигналов
независимо от фильтров задач. Для сигнала показаны время UTC, уровень, безопасная
причина, задача при наличии и состояние. Уровень сигнала не является severity
события Cowrie. Просмотр разрешён тем же человеческим ролям; сервисный токен его
не заменяет. Нет кнопок подтверждения, снятия тревоги или изменения настроек.

| Уровень | Код | Причина |
| --- | --- | --- |
| Предупреждение | `prompt_injection_detected` | Резервный анализ: обнаружена Prompt Injection |
| Предупреждение | `insufficient_rules` | Резервный анализ: недостаточно правил |
| Предупреждение | `guard_unavailable` | Резервный анализ: Guard недоступен |
| Предупреждение | `analysis_error` | Ошибка анализа задачи |
| Критический | `intake_capacity_reached` | Приём остановлен: очередь заполнена |
| Критический | `storage_unavailable` | Хранилище Core недоступно |
| Критический | `storage_failure` | Не удалось сохранить состояние задачи |
| Критический | `disk_full` | Диск заполнен |

Предупреждение — произошедший факт, без признака активной неисправности.
Критический эпизод имеет состояние «Активно» или «Устранено» и время устранения.
Повторное наблюдение одной причины/задачи не дублирует активный эпизод. Очередь
снова доступна при числе незавершённых задач меньше действующего лимита 1000;
ошибка сохранения состояния снимается только после завершения этой задачи.
Успешное чтение авторизованной страницы с доступной записью в БД снимает
`storage_unavailable`; отказ сохранения самой истории не считается восстановлением.
`disk_full` требует ENOSPC или подтверждённого нулевого свободного места/числа
inode по статистике файловой системы. Значение «число inode неизвестно» не
считается нулём свободных inode. При восстановлении записи и доступном месте
эпизод снимается; порог «мало места» не вводится.

При отказе БД страница возвращает 503 с «Core недоступен» и предложением
проверить журналы и контейнеры, без данных задач и деталей исключения. При
остановленном процессе такую страницу выдаёт существующий page ingress.
Ответы имеют `no-store`. Внешний независимый монитор и показ состояния
сборщика на странице в этот срез не входят. Границы сохранности — ADR 0007.

## Дополнение #46

`cowrie_event_type` также допускает `cowrie.login.success`, согласованно с
`login.outcome=success`. Несогласованные пары отклоняются с 422.
Начиная с #47 новая такая задача проходит queued → processing → completed
с High. Исторические failed-задачи #46 сохраняются без пересмотра.
Стабильный UUIDv5 строится из сенсора, поколения файла и байтового смещения;
received_at сохраняется при повторе. Правила источника и доставки — ADR 0003
и [runbook сборщика](../runbooks/cowrie-collector.md).

## Дополнение #48: команда и результат Guard

Пример команды с теми же обязательными полями происхождения:

```json
{
  "schema_version": 1,
  "event_id": "dffcc7c9-26f0-4d2a-aab1-021d14fa64b7",
  "occurred_at": "2026-10-23T08:00:00Z",
  "received_at": "2026-10-23T08:00:01Z",
  "event_type": "command",
  "cowrie_event_type": "cowrie.command.input",
  "sensor_id": "cowrie-lab",
  "session_id": "synthetic-command-session",
  "source_ip": "192.0.2.10",
  "source_port": 41000,
  "protocol": "telnet",
  "destination_port": 2223,
  "raw_record_ref": "synthetic:command-1",
  "command": {"text": "pwd"}
}
```

`command.text` — строго строка из 1–65536 символов. Дополнительно действуют
байтовые лимиты 64 KiB для сырой строки и нормализованного сообщения сборщика,
а также HTTP-тела на intake proxy: JSON-обрамление и UTF-8 тоже занимают место.
Число символов не означает, что команда такого же размера в байтах будет принята.
Пары `command/cowrie.command.input` и `login_attempt/cowrie.login.*` проверяются
на согласованность; неверная пара получает 422. UUIDv5, подтверждение 202,
повторная доставка и конфликт 409 работают как для входов. Команды не входят
в счётчик отказов входа. Нормализатор берёт только `input` и `session.connect`
provenance; Core не исполняет текст как shell-команду.

`analysis` команды содержит `analysis_method=Fallback`,
`rules_version=cowrie-command-v1`, `guard_result`, `reason_code`, `reason`,
`mitre_attack=null` и `evidence_ids`. Результат Guard имеет следующие поля:

| Поле | Значение |
| --- | --- |
| `status` | `blocked`, `no_match` или `error` |
| `score` | Максимальная оценка класса инъекции по окнам, 0–1; null при ошибке |
| `threshold` | 0.999; `score >= threshold` даёт `blocked` |
| `model_id` | `viavoice/mdeberta-ru-prompt-injection` |
| `revision` | `8e0fdb567ad0d1ddac0c9c1819b182204db26867` |
| `policy_version` | `cowrie-command-v1` |
| `window_count` | Число обработанных окон; 0 при отсутствии загрузки модели |
| `reason_code` | `prompt_injection_detected`, `no_injection_detected`, `model_not_configured`, `model_unavailable` или `scan_failed` |

Проверяется весь текст окнами по 256 токенов с перекрытием 64, результат —
максимум оценок. При ошибке частичная проверка не считается `no_match`.
Оценка не является калиброванной вероятностью безопасности.

| Guard | Состояние | Вердикт | `analysis.reason_code` |
| --- | --- | --- | --- |
| `blocked` | `completed` | severity=High, поля `analysis` и способ Fallback | `prompt_injection_detected` |
| `no_match` | `failed` | null, severity отсутствует | `insufficient_rules` |
| `error` | `failed` | null, severity отсутствует | `guard_unavailable` |

При `no_match` причина — «Недостаточно резервных правил для оценки команды»:
это не ошибка доступности Guard и не подтверждение безопасности команды.
MITRE ATT&CK во всех трёх случаях отображается как «не определена».
LLM Client отсутствует: внешнего вызова нет ни при одном результате.

Evidence сохраняет `id`, `event_id`, `raw_record_ref`, `source_kind` и безопасные
`facts`: `cowrie_event_type`, `protocol`, структурированный `guard_result`.
Текст команды находится в `event.command.text`, не дублируется в reason,
вердикте, Evidence или аудите. Дополнительные audit actions — `guard_checked`
и `fallback_warning`; завершение — `completed` либо `failed`. Локальный warning
`command_fallback` содержит task_id и код причины, без текста команды.

Завершённая задача при повторе и перезапуске сохраняет результат Guard,
Evidence и аудит; повтор не запускает переоценку. Исторические входы не меняются.
Карточка экранирует команду, список её не показывает. Приём и просмотр требуют
прежних TLS/token и SecOps-разрешений. Автоматическое удаление текста и истории
ещё не реализовано (#51); полный сырой источник пока не выдаётся (#49).
Запуск и диагностика — [runbook Guard](../runbooks/cowrie-command-guard.md).

## Дополнение #49: просмотр Evidence

При включённом evidence overlay авторизованные API и карточка добавляют к
Evidence поле `source_status`: `available`, `deleted`, `unavailable` или `synthetic`.
Для `available` также добавляются `excerpt`, `excerpt_truncated`, `raw_url`.
Фрагмент содержит до 512 Unicode-символов команды либо тип входа, протокол и
логин без пароля. Эти поля вычисляются при чтении; исходник в SQLite Core не
копируется. Синтетические источники не получают ссылку на сырой журнал.

`GET /api/tasks/{task_id}/evidence/{evidence_id}/raw` требует действующий сеанс
SecOps, DevOps или Auditor и принадлежность Evidence указанной задаче.
Ответ — одна исходная строка
Cowrie как `text/plain; charset=utf-8`, с прежними `no-store` и `nosniff`.
Карточка запрашивает её по нажатию ссылки и вставляет как текст, без HTML-разбора.
Браузер не передаёт reader путь, смещение или ссылку на произвольный источник.
Неизвестная задача/Evidence и синтетический источник дают 404; подтверждённое
отсутствие известной строки — 410 «Источник удалён»; отсутствие reader или
неподтверждённая доступность дают 503 без исходного текста в сообщении.

Core обращается к отдельному raw-reader по TLS с проверкой CA/имени и отдельным
сервисным токеном. Политика тех же трёх ролей защищает список, карточку и API
задачи; прочие роли получают 403, отсутствующий/истёкший сеанс — 401. Штатный
вход по-прежнему создаёт единственного SecOps; роль назначается сервером при
входе и сохраняется в сеансе, не выбирается HTTP-клиентом. Истечение через
30 минут бездействия и запрет продления через `poll=1` сохраняются. Ошибки
также получают `Cache-Control: no-store`. Сервисный токен не заменяет сеанс.

При `deleted` карточка показывает «Источник удалён», а поля `raw_url`, `excerpt`
и `excerpt_truncated` отсутствуют. Для команды `event.command.text` в ответе
карточки/API становится null; это проекция ответа, не изменение сохранённого
события и не физическое удаление копий по #51. Анализ, история и аудит не меняются.
При `unavailable` ссылка и фрагмент также не выдаются, но отметка удаления
не ставится. Если удаление ещё не подтверждено, Core читает источник через reader при
каждом запросе карточки/API; сырой текст проверки не входит в ответ и не хранится.
Поэтому доступность проверяется снова и при раскрытии по raw URL: удаление между
загрузкой страницы и нажатием ссылки даёт 410 и скрывает устаревшую ссылку/текст.

Reader считает удаление подтверждённым лишь для известного поколения при
доступных реестре и каталоге и проверенном отсутствии исходного файла/строки.
При ротации ищется прежняя идентичность файла среди `cowrie.json*` независимо
от последнего имени в реестре. Подмена, ошибки доступа и возможный `.gz`-архив
означают неопределённость. Неизвестное поколение не является доказательством
удаления. Поиск ограничен 1000 именами; превышение даёт недоступность, не удаление.
Подтверждение удаления сохраняется в метаданных Core как ID события и время
первого подтверждения, без текста. Последующая недоступность reader, его
отключение или перезапуск Core не отменяют известное удаление: карточка остаётся
`deleted`, raw URL — 410. Неподтверждённая недоступность такую отметку не создаёт.
Очистка этой отметки вместе с метаданными задачи относится к #51.
Решения — [ADR 0006](../adr/0006-evidence-raw-source.md),
включение — [runbook Evidence](../runbooks/evidence-source.md).
