## Результат реализации

Core удаляет текст через 14 суток, связанные безопасные данные задачи — через
30 суток от первого приёма. Отдельный очиститель покрывает Cowrie JSON, карантин,
TTY, служебные и stdin/redirection-копии, gzip; collector обслуживает outbox/chunks.
Evidence подтверждает удалённый источник без фрагмента, а не делает вывод только
по истечению срока. Незавершённые команды без текста завершаются failed с сигналом;
Rules для входа могут продолжить работу по оставшимся полям.

### Исправления, найденные полной приёмкой

Штатный Cowrie создаёт служебный `cowrie.log` с режимом 0644, а временные
артефакты могут иметь 0600. Первоначальный очиститель UID 10001 не мог их менять,
несмотря на дополнительную группу 999: реальный CLI воспроизводил PermissionError,
сервис оставался unhealthy. Исправлена модель доступа без root/capabilities:

| Actor | Права |
| --- | --- |
| Cowrie | Прежний UID/GID 999; logs/downloads и состояние сессий |
| Collector | Прежний UID 10001 + группа 999; directory реестра 2770, SQLite/journal/lock 0660; приватные chunks 0700/0600 |
| Retention | UID/GID 999, владелец текстовых файлов; общий реестр по группе; нет сети, портов, Docker socket, Core SQLite, TLS/пароля/токенов/модели и SSH-ключей Cowrie |
| Reader | UID 10001 + группа 999; прежние read-only mounts; gzip-результат 0640 |
| Core | Приватные `/data` 0700 и SQLite, UID/GID 10001 |

Collector выполняет групповую миграцию своего реестра как его владелец, до
readiness. Код не выдаёт 777 и не требует chown/root во внешнем host. Совместный
flock/SQLite-протокол сохраняется. Очистка chunks выполняется собственным
supervisor collector после остановки только дочернего Fluent Bit.

Semgrep отдельно выявил лишний групповой write у gzip-результата. Он сужен
с 0660 до 0640: запись нужна только владельцу-очистителю, reader получает read
через группу и read-only mount. SAST-подавление для этого не добавлялось.
Вся временная диагностика `[DEBUG-51-retention]` удалена.

### Сценарий с настоящим Cowrie и Guard

`test_retention_stack_runtime.py` поднимает 11 сервисов со штатными production
Dockerfiles и overlays, добавляя только read-only тестовый clock/entrypoint.
Общий clock передан публичным конструкторам Core, collector, reader и CLI;
production HTTP-настройка времени не добавлена. Веса Guard локальные,
закреплённые; внешняя LLM отсутствует.

Проверяются:

- Настоящая сессия Cowrie → Fluent Bit → TLS intake → Core/Guard High → карточка
  и сырой источник reader по TLS; отдельная сессия на сутки позже.
- Настоящая команда перенаправления создаёт копию в downloads; до срока тест
  положительно подтверждает наличие её маркера, затем проверяет удаление.
- На границе 14 дней old text отсутствует в файлах logs/TTY/downloads, Core SQLite,
  collector SQLite/chunks и соответствующих tmpfs. Приватные файлы читаются
  тем actor, которому принадлежат, без расширения его полномочий для теста.
- Сохраняются прежний High и безопасные метаданные; Evidence deleted без excerpt,
  старый raw URL даёт 410. Новая команда и её собственный срок сохраняются.
- Проверяется сжатая копия: старый маркер исчезает, свежий остаётся; реальный UID
  reader читает результат 0640 через группу при read-only mount.
- Container ID Cowrie не меняется, исходная TCP-сессия принимает `pwd` после
  очистки: фонового перезапуска/остановки Cowrie нет.
- На 30 днях старая задача даёт 404, более свежая ещё доступна; после пересоздания
  Core старая задача не возвращается.

Неатрибутированные вспомогательные копии используют самый ранний из возможных
сроков, по согласованной политике. Это может удалять их раньше собственных 14
суток; основные JSON-записи/Core сохраняют индивидуальный receipt. Тест не
доказывает восстановимость исходного текста после его очистки или качество
классификации на реальном потоке.

## Security gate

Первый gate обнаружил исправленную HIGH CVE-2026-84782 OpenSSL в закэшированном
smoke-образе (libssl3/openssl `3.0.22-1~deb12u1`, исправление `3.0.22-1~deb12u2`).
Образ пересобран с `--no-cache --pull` и штатным apt upgrade, без исключения CVE.
Затем повторён полный gate с отдельным каталогом итоговых отчётов.

Итоговые отчёты включают pip-audit, Gitleaks, Semgrep, Trivy filesystem/config и
четыре image scans (smoke/Core/collector/Guard), проверку security exceptions и
CycloneDX SBOM. Применяется существующая политика проекта HIGH/CRITICAL с
`--ignore-unfixed`; новых исключений не добавлено. Core дополнительно проверен
Semgrep явно с `--no-git-ignore`, включая новые файлы.

## Runbook и доказательства

Новый [runbook retention](../runbooks/retention.md) описывает полный набор
overlays, режимы, CLI трёх ролей, ошибки/recovery, закрытые gzip, остановку без
удаления томов и одноразовое обновление со сменой Cowrie logger. При этом
однократное пересоздание Cowrie при обновлении явно завершает сессии; оно
отличается от фоновой очистки, которая Cowrie не останавливает.
Ссылки и устаревшие утверждения обновлены в README и прежних runbooks.

Все запуски выполнялись на тестовых томах. Команды config/up/CLI/проверки прав,
фактических файлов, готовности, сохранности после пересоздания и down собственных
томов входят в harness. Для чужого нестандартного logging driver внешние копии
требуют собственной политики удаления; очиститель не получает Docker socket.
