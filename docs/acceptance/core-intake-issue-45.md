Коммит реализации: `de1a7f2e002aab918df51627ac7e11829dacc54e`.
Последующий коммит усиливает runtime-проверку одновременного запуска восьми
сервисов; приложение и согласованные контракты при этом не меняются.

## Acceptance criteria

- [x] Защищённый внутренний приём возвращает номер задачи без ожидания анализа;
  задача проходит согласованные состояния, а вердикт, Evidence и запись аудита
  сохраняются в SQLite на отдельном томе.
- [x] Единственный пользователь SecOps входит по существующему лабораторному
  паролю; хранится только его хеш, успешный вход записывается, сеанс заканчивается
  после 30 минут бездействия. Страница доступна по согласованному HTTP и только
  для просмотра.
- [x] Сквозная проверка подаёт синтетическое нормализованное событие и наблюдает
  номер задачи и Low на странице; неавторизованный доступ к внутреннему приёму
  и странице отклоняется.

Пароль настоящего стенда вводится оператором локально через
`scripts/core_credentials.py`. Автоматизированные тесты и браузерная проверка
использовали только известный синтетический пароль и RFC 5737 IP-адрес.
Сырые пароли Cowrie и команды не входят в контракт этого среза.

повторная доставка не добавляет анализ. Из Cowrie и Target App проверяются DNS-имена и
прямые IP каждого управляющего сервиса. Старые runtime-тесты Phase 1 продолжают
проверять SSH/Telnet, HTTP ingress, сырые журналы, egress и изоляцию prod_net.

## Границы и откат

Это первый срез #44: нормализованный отказ входа и Low, без реального сборщика,
серий/успешных входов, команд, LLM, просмотра сырого журнала и retention jobs.
Прямой HTTP страницы и отсутствие резервной копии SQLite — согласованные
ограничения лаборатории. Удаление рабочего тома означает потерю истории.
Откат: остановить объединённый project без `-v`, сохранить `core-data` и
запустить прежний Phase 1 Compose без Core overlay. Все тестовые контейнеры и
тома удаляются только в пределах собственных случайно названных test projects.
