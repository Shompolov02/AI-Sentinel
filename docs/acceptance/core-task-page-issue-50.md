## Acceptance criteria

Формулировки из #50; отметки подтверждают локальную приёмку:

- [x] Список показывает время, тип события, состояние и уровень угрозы; поиск по номеру и фильтр состояния находят реальные задачи.
- [x] Состояние обрабатываемой задачи автоматически обновляется примерно раз в 10 секунд без изменения настроек через страницу.
- [x] Страница показывает относящиеся к Core предупреждения и критические тревоги; оператор по-прежнему может проверить локальный журнал и состояние контейнеров.

## Проверенные возможности

- Поиск по полному UUID или буквальной подстроке, без учёта регистра,
  совместно с состоянием. Условия применяются до ограничения 100 результатов:
  HTTP-тест находит задачу за пределами первоначальных 100 строк.
- Форма сохраняет условия и при автообновлении. Есть сброс и пустая выдача;
  символы `%`/`_` не работают как шаблоны, HTML запроса экранируется.
- Список и незавершённая карточка содержат интервал обновления 10 секунд.
  Карточка перечитывает результат через GET с `poll=1`; после completed/failed
  перестаёт обновляться. Обновления не меняют задачу и не продлевают сеанс.
- Управляемое время проверяет HTTP-доступ на 1799-й секунде и отказ на 1800-й
  для списка, карточки и API после фоновых чтений. Ответ 401 не содержит данных
  задачи и дальнейшего автообновления. Страница не допускает POST для изменения
  задачи.

## Сигналы Core — пункт 7

Владелец согласовал каталог причин, историю последних 100 сигналов плюс
текущие критические проблемы и аварийную страницу 503. Решения — ADR 0007;
коды и порядок восстановления перечислены в контракте и runbook.

Новые сценарии шли последовательными red/green циклами: Fallback в истории,
503 при блокировке SQLite, переполнение очереди, ENOSPC, ошибка анализа при
возможности сохранить failed и критическая ошибка сохранения состояния.
Для отказов использована настоящая блокировка SQLite на границе хранилища;
ENOSPC управляемо подаётся на этой же системной границе, без заполнения диска
пользователя. Состояния и результаты наблюдаются через HTTP и локальные логи.
Дополнительно проверены права, предел 100 записей, одинаковые временные метки,
отсутствие текста команды, повторная доставка и сохранность после перезапуска.

- Core/list/refresh/alerts/Evidence/Guard/login rules: **67 passed**.
- Общий `make test` после добавления сигналов: **141 passed**, без skips,
  **19 runtime deselected**; включая Docker smoke, недоступный прежнему запуску.
- Strict mypy: **42 файла**, без ошибок. Ruff check/format и diff check: PASS.
- Новый отдельный runtime ingress: **1 passed**. Настоящий Nginx с текущей
  конфигурацией при отсутствии Core возвращает безопасный 503, после запуска
  настоящего Core снова позволяет вход и просмотр, а после его остановки опять
  показывает 503. Внутренний intake через page ingress остаётся недоступен.

Браузерный опыт использовал собственную временную SQLite и синтетические

а история сохранила «Устранено». Скриншоты:
`.artifacts/issue50-alerts-active.png`, `issue50-alerts-history.png`.

Отдельная реальная блокировка этой временной базы привела браузер к 503 без
данных задач. После снятия блокировки и перечитывания страницы история
сохранила «Хранилище Core недоступно / Устранено». Снимок аварийной страницы —
`.artifacts/issue50-alerts-unavailable.png`.

Это компонентные runtime-проверки, не замена полной Compose-приёмке из Cowrie.
