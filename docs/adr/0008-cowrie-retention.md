# Сроки хранения текста Cowrie и метаданных Core (#51)

Политика и границы проверок согласованы владельцем 2026-10-26. Решение
реализовано для основных хранилищ текста в пункте 6 и метаданных в пункте 7.
Полная приёмка пункта 9 выполнена 2026-10-27:
[отчёт](../acceptance/retention-issue-51-step-9.md). Поддержка gzip реализована;
[проверки и эксплуатационные границы](../acceptance/retention-issue-51-gzip.md).
Локальные проверки — [пункт 6](../acceptance/retention-issue-51-step-6.md)
и [пункт 7](../acceptance/retention-issue-51-step-7.md).

Сохраняем одну SQLite Core: удаляемый через 14 дней текст отделяется от
30-дневных метаданных. Срок текста начинается с первого приёма исходной записи
телеметрией и не обновляется при доставке, обработке, копировании или повторе.
Очистка просроченных outbox/chunks входит в #51; размеры буфера и поведение при
перегрузке остаются #52. Новая база Core, брокер и внешняя LLM не добавляются.

Владелец выбрал фоновую очистку без плановой остановки Cowrie, с сохранением
активных сессий, свежих данных, TTY и служебных журналов. Поэтому нельзя удалять
целый смешанный файл по его возрасту или сдвигать свежие строки: удаляемые диапазоны
обезличиваются на месте, а подтверждение операции сохраняется без исходного текста.
Core и collector сохраняют прежние UID; отдельный локальный процесс очистки
получает только необходимые тома, без сети, Docker socket и секретов Core.

Контейнерная проверка выявила, что штатный `cowrie.log` имеет режим 0644,
а открытые временные артефакты могут иметь 0600. Поэтому очиститель работает
как их владелец Cowrie (UID/GID 999), без root и capabilities. Collector UID
10001 настраивает только свой реестр и lock/journal для общей группы 999
(каталог 2770, файлы 0660); Core SQLite и секреты остаются приватными. Chunks
остаются приватными collector и очищаются его собственным supervisor. Gzip-
результаты читаются reader через ту же группу, при read-only mounts. Запуск
очистителя UID 10001 с одной дополнительной группой не позволяет стереть
активный файл 0600; root/CAP_DAC_OVERRIDE и второй процесс, постоянно меняющий
права Cowrie, не добавляются.

Уточнение владельца при реализации пункта 6: TTY, служебные журналы и прочие
вспомогательные копии получают срок от первого приёма начала сессии. Это
допускает раннее удаление свежих фрагментов долгой сессии. Основная Cowrie
JSON-запись и команда Core сохраняют собственный срок записи. Такой вариант
выбран вместо внедрения в Cowrie меток происхождения каждой команды: штатный
TTY-кадр не определяет происхождение позднего вывода. Сопоставление по сходству
текста или ближайшему времени не используется.

Для исторического текста с известным временем приёма сохраняем исходный срок.
Владелец разрешил при миграции удалить только текст, срок которого достоверно
восстановить нельзя, сохранив допустимые метаданные. Подмена неизвестного времени
датой обновления и новый 14-дневный срок запрещены. Эта операция является частью
будущей миграции; согласование не означает, что пользовательские данные уже удалены.

Отдельные SQLite для текста и метаданных отклонены из-за дополнительных границ
согласованности. Скрытие текста только в HTTP, неограниченное хранение копий
в Docker stdout, отключение TTY и плановая остановка Cowrie не соответствуют
выбранной политике. Штатный stdout logger Cowrie заменяется его файловым logger,
с сохранением служебного журнала в очищаемом томе.

Технический контракт, восстановление после сбоя и согласованные TDD seams:
[core-retention-v1.md](../spec/core-retention-v1.md). Каждая техническая гарантия
должна быть подтверждена при реализации; этот ADR не заменяет приёмку.
