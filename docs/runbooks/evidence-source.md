# Просмотр исходной записи Cowrie (#49)

Для политики 14/30 дней используйте полный набор overlays и порядок обновления
из [runbook retention #51](retention.md). Core очищает свою базу самостоятельно;
сырьё, TTY и служебные копии требуют retention overlay.

Требуется существующий Core со сборщиком из [runbook #46](cowrie-collector.md).
Чтение разрешено ролям SecOps, DevOps и Auditor; остальные роли получают 403,
отсутствующий или истёкший сеанс — 401. Подтверждённое удаление источника
отображается отдельной отметкой без ссылки и фрагмента.
Очистка по сроку включается по runbook #51; используйте синтетические данные.

Добавьте сертификат и отдельный сервисный токен reader, не меняя пароль Core,
intake-сертификат и токены сборщика:

```sh
sh scripts/raw_reader_credentials.sh secrets/core
docker compose -f deploy/docker-compose.yml -f deploy/core.compose.yml -f deploy/collector.compose.yml -f deploy/evidence.compose.yml config --quiet
docker compose -f deploy/docker-compose.yml -f deploy/core.compose.yml -f deploy/collector.compose.yml -f deploy/evidence.compose.yml up -d --build --wait
```

При использовании Guard сохраните также `-f deploy/guard.compose.yml` во всех
командах. Reader запускается из обычного runtime-образа и не требует ML-весов.
Скрипт отказывается перезаписывать reader-файлы. Закрытый ключ CA остаётся на
хосте; токен reader не передаётся сборщику и не используется для входа человека.

Войдите в Core, создайте синтетическую команду через Cowrie и откройте карточку
задачи. Evidence показывает фрагмент до 512 символов и отметку сокращения.
«Показать исходную запись» раскрывает единственную JSON-строку как обычный текст
внутри карточки; HTML/скрипты из неё не должны выполняться. Исходник не появляется
в списке задач. Пароль входа виден только при открытии соответствующей сырой строки.

Штатный запуск сохраняет единственного пользователя SecOps. Роль назначается
сервером и сохраняется в сеансе; заголовки, query-параметры и JSON запроса входа
её не меняют. Настройки через HTTP для ролей и создания пользователей нет.
Перед доступом второго человека потребуется отдельная учётная запись.
Существующие сеансы при обновлении сохраняют роль SecOps и прежний срок жизни.

Проверьте: без входа (в том числе с одним токеном сборщика) карточка, API задачи
и сырой источник возвращают 401. После 30 минут бездействия — также 401;
`poll=1` не продлевает сеанс, явный просмотр продлевает. Ответы страницы,
Evidence и источника, включая ошибки, содержат `Cache-Control: no-store`.

Raw-reader не публикует порт и имеет только read-only mounts журнала и реестра.
Если удаление ещё не подтверждено, при открытии карточки или API задачи Core
проверяет источник через reader,
не сохраняя полученный сырой текст. Ссылка и фрагмент показываются только после
успешной проверки. Ответ reader ограничен по объёму, timeout клиента — 3 секунды.

В тестовом стенде проверьте следующие случаи, используя только отдельный
синтетический журнал и сохраняя реальные данные:

- Переименование `cowrie.json` в `cowrie.json.1` сохраняет доступ к той же строке,
  даже до следующего сканирования сборщиком.
- После удаления известного файла из доступного каталога карточка показывает
  «Источник удалён», не показывает ссылку и фрагмент; текст команды скрывается
  также в разделе события и API карточки. Ранее полученный raw URL даёт 410.
- Если удаление произошло после загрузки карточки, нажатие ссылки получает 410
  и убирает ссылку и текст в уже открытой странице.
- Если reader, реестр или каталог недоступны, карточка сообщает о временной
  недоступности без утверждения об удалении. Подмена файла, symlink, неизвестное
  поколение и неподтверждённый архив `.gz` также не считаются доказательством
  удаления. Зарегистрированный gzip поддерживается очистителем и reader. После
  восстановления проверка повторяется, ссылка на доступный источник возвращается.

Подтверждённое удаление сохраняется в метаданных Core без текста и остаётся
известным после перезапуска, остановки reader и отката overlay. Прочие статусы
проверяются при чтении; результат анализа и аудит задачи не переписываются.
Срез #51 удаляет текст из всех подключённых хранилищ через 14 суток, а
метаданные — через 30 суток. Само отсутствие текста в карточке не доказывает
физическую очистку SQLite: проверяйте CLI и состояние очистителя по runbook #51.
Подтверждение удаления в Core сохраняется до срока метаданных, в том числе
после очистки реестра диапазонов. Без подтверждения неизвестная ссылка
считается непроверенной, а не удалённой.

Остановка без удаления данных: повторите полный набор overlays с `down`, без `-v`.
Для отключения просмотра уберите evidence overlay, пересоздайте Core и удалите
осиротевший reader через Compose `--remove-orphans`, сохранив named volumes.

Автоматизированная приёмка: `make test-core-runtime` проверяет десятисервисный
вариант со сборщиком и reader, а также прежний восьмисервисный вариант Core.
`make test-command-runtime` дополнительно требует реальные веса Guard и
`CORE_GUARD_MODEL_DIR`; полный набор — `make test-runtime`. Для повторного
прогона можно задать `AI_SENTINEL_RUNTIME_REUSE_IMAGES=1`, только если образы
уже собраны из проверяемого рабочего дерева. Harness использует отдельный
случайно названный Compose project, временные credentials и собственные тома.
Он проверяет остановку без `-v`, отключение/возврат overlay и сохранность
метаданных, а в конце удаляет только свои тестовые тома.
